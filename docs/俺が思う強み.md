# コンテスト向けアピールポイント整理

## 1. コンセプトの革新性：「速さ」から「確実性」へのパラダイムシフト
既存の乗換案内は「いかに速く着くか」の競争だが、本アプリは**「いかに確実に、安心して着くか」**に振り切っている。

*   **未来リスクの可視化**:
    *   従来のアプリ：「現在の遅延」しか教えてくれない。
    *   本アプリ：「過去の統計」×「イベント情報」×「リアルタイム状況」を組み合わせ、**「今は遅れていないが、これから遅れるかもしれないリスク」**を可視化。
    *   「絶対に遅刻できない」というユーザーの切実なニーズ（ペインポイント）を解決する。

## 2. 技術的優位性：APIラッパーではない「独自探索エンジン」
既存のAPIをただ叩いて表示するだけではなく、コア技術を自前で実装している点がエンジニアリングとしての最大の強み。

*   **独自の経路探索エンジンの実装**:
    *   グラフ構造の構築から探索アルゴリズム（ダイクストラ法）をゼロから独自実装。
    *   **「乗り換え抵抗（Transfer Buffer）」を動的に変動させるロジック**を実装。通常の「最短」だけでなく「少し遅くても乗り換えが少ないルート」など、多様なニーズに応えるルート生成が可能。
    *   また、発見したルートにペナルティを与えて再探索する**「ペナルティ法」により、地理的に異なる複数のルート候補（迂回ルートなど）を強制的に提案**できる仕組みを構築。これらは一般的なAPIでは制御できない部分。
*   **Predictive Risk Engine (予測エンジン)**:
    *   過去の遅延データとイベント情報を統計分析し、リスクスコアを算出するロジックを構築。

## 3. UX/UIデザイン：意思決定をデザインする
「データを並べる」のではなく、「ユーザーが選びやすくする」ための工夫。

*   **4軸評価システム（速さ・快適・安定・安さ）**:
    *   単一の正解（最短ルート）を押し付けるのではなく、ユーザーの状況（急ぎ、荷物が多い、安く行きたい）に合わせて選択できる「判断材料」を提供。
*   **AI Concierge (生成AI活用)**:
    *   データの羅列になりがちな詳細情報を、LLMが「文脈」として解釈。
    *   「この時間は混雑イベントと重なるので避けたほうがいい」といった、人間味のある定性的なアドバイスを実現。
